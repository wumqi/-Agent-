IT 运维故障处理手册

一、故障分级标准
P0（紧急）：核心业务系统全面瘫痪，影响全部用户，需 15 分钟内响应，2 小时内恢复。
P1（严重）：核心功能不可用但有替代方案，影响大部分用户，需 30 分钟内响应，4 小时内恢复。
P2（一般）：非核心功能异常，影响部分用户，需 2 小时内响应，24 小时内恢复。
P3（轻微）：界面显示问题、文案错误等，影响极小，需 8 小时内响应，72 小时内修复。

二、故障报告流程
1. 发现故障后，第一时间在工单系统中提交故障工单，选择"IT运维"分类。
2. 工单标题格式：【PX】系统名称 - 故障简述，例如【P1】CRM系统 - 订单查询超时。
3. 工单内容需包含：故障现象、影响范围、复现步骤、截图或日志。
4. 运维值班人员收到工单后立即评估并确认故障等级。
5. P0/P1 故障同时电话通知运维经理和技术总监。

三、常见故障及处理方法

3.1 服务器无法访问
可能原因：网络中断、服务器宕机、防火墙规则异常。
处理步骤：
1. 使用 ping 命令测试网络连通性。
2. 检查云平台控制台，确认实例运行状态。
3. 远程登录服务器检查系统日志（/var/log/syslog 或 /var/log/messages）。
4. 检查防火墙规则和安全组配置。
5. 如服务器宕机，尝试重启；如无法恢复，启用备机并通知团队。

3.2 数据库连接超时
可能原因：连接数耗尽、慢查询阻塞、磁盘空间不足。
处理步骤：
1. 查看数据库连接池状态：SHOW PROCESSLIST。
2. 检查慢查询日志，终止长时间运行的查询：KILL <process_id>。
3. 检查磁盘空间：df -h，如空间不足立即清理日志或扩容。
4. 检查数据库参数：max_connections、wait_timeout 是否合理。
5. 临时措施：重启数据库连接池或重启应用服务。

3.3 应用接口响应缓慢
可能原因：代码性能问题、外部依赖超时、JVM内存不足。
处理步骤：
1. 查看应用监控：CPU、内存、GC 频率。
2. 检查接口调用链路，定位耗时最长的环节。
3. 如果是 JVM 内存问题，导出 heap dump 后重启应用。
4. 如果是外部依赖超时，检查第三方服务状态并启用熔断降级。
5. 必要时水平扩容增加应用实例。

3.4 磁盘空间告警
可能原因：日志文件过大、临时文件未清理、数据增长超出预期。
处理步骤：
1. 使用 du -sh /path/* 找到占用最大的目录。
2. 清理过期日志：find /var/log -name "*.log" -mtime +30 -delete。
3. 清理 Docker 无用镜像和容器：docker system prune -f。
4. 如磁盘频繁告警，申请扩容或调整日志轮转策略。

四、故障复盘
1. P0/P1 故障恢复后 48 小时内必须召开复盘会议。
2. 复盘报告包含：时间线、根因分析、影响评估、改进措施。
3. 改进措施需明确责任人和完成日期，录入项目管理系统跟踪。

五、值班制度
1. 运维团队实行 7×24 小时轮值制度，每人值班一周。
2. 值班期间手机保持畅通，收到告警 5 分钟内响应。
3. 值班交接在每周一上午 10:00 进行，交接内容包括：当前遗留问题、待关注事项、本周变更计划。
