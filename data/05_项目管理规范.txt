项目管理规范

一、项目立项
1. 所有项目启动前须提交《项目立项申请书》，经部门总监审批后方可启动。
2. 立项申请内容包括：项目背景、目标、范围、预算、人员需求、里程碑计划。
3. 预算超过 50 万元的项目需经总经理审批。
4. 立项通过后由 PMO 分配项目编号并在项目管理系统中创建项目空间。

二、项目角色与职责
1. 项目经理（PM）：负责项目整体规划、进度跟踪、风险管控和干系人沟通。
2. 产品经理（PD）：负责需求分析、产品设计和验收标准制定。
3. 技术负责人（TL）：负责技术方案选型、架构设计和代码质量把控。
4. 开发工程师：按照技术方案完成编码、单元测试和代码评审。
5. 测试工程师：制定测试计划、编写测试用例、执行测试并输出报告。
6. 运维工程师：负责环境搭建、部署上线和运行监控。

三、需求管理
1. 需求来源包括：客户反馈、产品规划、运营建议、技术债务。
2. 所有需求须录入需求管理系统，包含：优先级、描述、验收标准、预估工时。
3. 需求优先级分为 P0（紧急）、P1（高）、P2（中）、P3（低）。
4. 需求变更须提交变更申请，经项目经理和产品经理双签后生效。
5. 需求冻结后不再接受变更，紧急变更需总监特批并评估影响。

四、开发流程
1. 代码分支策略采用 Git Flow：main（生产）、develop（开发）、feature/*（功能）、hotfix/*（修复）。
2. 所有代码提交须关联需求或缺陷编号，提交信息格式：[类型] #编号 简述。
3. 功能开发完成后须发起 Code Review，至少一名同级或高级工程师审核通过。
4. 代码合并到 develop 分支后自动触发 CI 流水线，包含：编译、单测、静态扫描。
5. 静态扫描严重问题数为 0 方可合并。

五、测试流程
1. 测试阶段划分：单元测试 → 集成测试 → 系统测试 → 验收测试。
2. 单元测试由开发人员编写，代码覆盖率要求不低于 60%。
3. 系统测试由测试团队执行，严重缺陷必须全部修复后方可进入验收阶段。
4. 缺陷等级：致命（Blocker）、严重（Critical）、一般（Major）、轻微（Minor）。
5. 上线标准：无致命和严重缺陷，一般缺陷遗留不超过 3 个且有明确修复计划。

六、上线与发布
1. 上线前须完成：上线检查清单确认、回滚方案准备、相关方通知。
2. 生产环境发布窗口为工作日 18:00-22:00 或周末 10:00-18:00。
3. 发布采用灰度策略：先 1% → 10% → 50% → 100%，每阶段观察 30 分钟。
4. 发布过程中出现严重问题立即执行回滚，确保 15 分钟内恢复。
5. 发布完成后 24 小时内为观察期，运维重点关注系统指标和用户反馈。

七、项目复盘
1. 每个项目或迭代结束后 1 周内召开复盘会议。
2. 复盘内容：目标达成情况、做得好的方面、待改进的方面、行动计划。
3. 复盘结论录入知识库，供后续项目参考。
4. 行动计划需指定责任人和截止日期，在下次复盘时检查完成情况。

八、项目沟通
1. 每日站会：15 分钟内完成，每人汇报昨日完成、今日计划、阻塞问题。
2. 周报：每周五下班前提交，内容包括本周进展、下周计划、风险预警。
3. 里程碑会议：每个里程碑节点召开评审会，确认交付物和下阶段计划。
4. 客户沟通：项目经理每两周向客户汇报一次项目进展，重大事项即时同步。
